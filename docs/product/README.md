# Product design

Product design docs define **what Cabin is for** and **which features earn a
place** — before architecture and component contracts say how to build them.

Engineering principles live in [principles](../principles.md). Compliance
mechanics live in [compliance](../compliance/README.md). This section is the
product filter those layers serve.

## Documents

| Document | Description |
| --- | --- |
| [Stance](stance.md) | Calm, legible, inevitable cabin HMI — clarity, restraint, craft |
| [Pillars](pillars.md) | Five gates every feature must pass |
| [Features](features.md) | Layered feature plan (Foundations → System → Core → Patterns → Craft) |

## How to use this section

1. Read [stance](stance.md) for the product posture.
2. Run proposals through [pillars](pillars.md).
3. Place work in the [feature layers](features.md) and respect v1 non-goals.
4. Sequence delivery with the [roadmap](../roadmap.md).
